# 评测数据虚构性扫描器（S5-EVAL-007）

命令 `eval-pii-scan`：在用例入库前与 CI 中扫描评测集、context 文件与样例文档，拦截看起来真实的敏感数据。8 类检测项 + 企业名/人名两类告警，error 级阻断 CI（退出码 1），warn 级只进报告（退出码 0）。

## 一条命令复跑

```
python pkg/engine.py                    # 重算 data/（夹具与 1000 条性能用例）
python tools/verify.py                  # 逐条断言 AC（31 条），非零退出可接 CI
python -m pytest tests -v               # 单元测试（60 项）
python tools/mutate.py                  # 变异自检：改坏 14 处，每处都必须让 verify 变红
python tools/build_docs.py              # 由实跑结果重生成本文档与 ACCEPTANCE
python tools/make_zip.py                # 打包 + SHA256SUMS
```

依赖：Python 3.11+，无第三方库。

## eval-pii-scan 用法

```
python -m pkg.cmd data/fixtures
python -m pkg.cmd data/fixtures --allowlist data/allowlist.yaml
python -m pkg.cmd data/perf1000 --json --report docs/scan_report.md
```

退出码：**0 无 error 级命中（可能只有 warn）/ 1 有 error 级命中（阻断 CI）/ 2 用法或配置错误**。
「阻断」与「配置错」用不同退出码：把配错的 allowlist 当成命中，CI 里会误导排查方向。

## 8 类检测项与分级

| 检测项 | 判定依据 | 级别 |
| --- | --- | --- |
| 手机号 | `1[3-9]` 开头 11 位 | **error** |
| 身份证 | 18 位 + ISO 7064 MOD 11-2 校验位 | **error** |
| 银行卡 | 16~19 位 + Luhn 校验 | **error** |
| 统一社会信用代码 | 18 位 + GB 32100 校验位，且第 3~8 位不是 `999999` | **error** |
| 固定电话 | `0` + 2~3 位区号 + 7~8 位号码 | warn |
| 邮箱 | 标准邮箱形态 | warn |
| 详细地址 | 省/市/区之一 + 路号，且在 20 字窗口内 | warn |
| 车牌号 | 省份简称 + 字母 + 5~6 位 | warn |
| 企业名称 | 未带「示例」或「（虚构）」标记 | warn |
| 中文人名 | 角色词（记录人/负责人/联系人…）后 2~4 字，未带「（虚构）」后缀 | warn |

## allowlist

每条必须写 `value` / `confirmed_by` / `confirmed_on`，`kind` 与 `reason` 可选。
**格式不合规直接报错（退出码 2）**，不静默跳过 —— 否则白名单失效时没人知道。
白名单只放行指定的那一条，不会连带放行同类其他命中。

## 三条容易写错的口径

**① 正则只负责切片，是否命中交给校验位。**
身份证、银行卡、信用代码三类都是「形态匹配 + 校验位通过」才算命中，所以正反例的差别可以精确到一位数字（本包的正反例就只差校验位）。信用代码还有一条附加规则：第 3~8 位为 `999999` 视为占位号段、不报。这里有个坑 —— 占位号段的校验位**也要是合法的**，否则它会先被校验位拦掉，「排除占位」那段就成了永远走不到的死代码（本包第一版就是这样，变异测试直接抓出来的）。

**② 中文人名不能靠纯正则边界识别。**
`[\u4e00-\u9fa5]{2,4}` 贪婪匹配会把「张三负责」整体当成 4 字人名。做法是只在角色词（记录人 / 负责人 / 联系人 / 参会人 / 审批人 / 经办人 …）之后取候选，并且默认取 2 字、前两字是复姓时才取 3 字。

**③ 性能口径要区分冷启动与稳态。**
1000 条用例实测：冷启动 19.8 秒、稳态 0.13 秒 —— 差 150 倍，差别全部来自 1000 个新建小文件在 Windows 上被逐文件做实时防护扫描。所以性能夹具取 JSONL 单文件形态（评测集本来就是这么存的），并按「预热 2 轮后取 3 次稳态最小值」口径判定；冷启动耗时同时记录在报告里，不做隐瞒。

## 设计取舍

- **四类走校验位而不是纯正则**：手机号 11 位数字在合同编号里也常见，纯正则误报率高；身份证、银行卡、信用代码有官方校验位，用它判定可解释、可复现。
- **「阻断」与「配置错」分两个退出码**：CI 里 1 表示「数据有问题」、2 表示「工具或配置有问题」，混在一起会把配错的 allowlist 当成人身数据泄露去排查。
- **白名单强制写确认人与日期**：没有这条约束，白名单会变成「一键忽略」，半年后没人知道某条为什么被放行。
- **性能夹具里塞了命中样例**：只放干净文本测的是「快速跳过」路径，不是最坏情况；本包每 97 条插入一条含手机号+身份证的用例。
