# 客服转人工 SOP：转接规则与响应时限

本包为「客服转人工 SOP：转接规则与响应时限」交付物：6 条转接触发条件（每条写明接手岗位与档位）+ 双时段响应时限表（工作时间就地起算、非工作时间顺延到下一工作日 09:00）+ 处理流程图（Mermaid 11 节点，含两级升级路径）+ 待办生成与超时升级规则 + 知识缺口回写字段与规则 + 8 个响应时限判定示例。全部内容为**虚构**。

## 一条命令复跑

```
python tools/gen.py             # 重新生成 docs/ 下全部交付物
python tools/verify.py          # 逐条断言 AC（23 条），任何一条失败即非零退出
python -m pytest tests -q       # 用例逐条比对 CSV 期望值
python tools/mutate.py          # 变异测试：改坏引擎 7 处，每处都必须让 verify 变红
python tools/build_docs.py      # 由实跑结果重生成 README / DATA_PROVENANCE / ACCEPTANCE
python tools/make_zip.py        # 打包 + SHA256SUMS
```

## 口径说明

- 工作时间 = 工作日（周一~周五）09:00–18:00；非工作时间 = 工作日 18:00–次日 09:00、周末、节假日。
- 双时段时限：普通转接 30 分钟、紧急转接 15 分钟；时长只在工作时间内消耗。
- 工作时间提出就地起算（周三 10:00 → 10:30 前）；非工作时间提出顺延到下一工作日 09:00 起算（周三 19:00 → 周四 09:30 前）。
- 紧急档（15 分钟）用于涉及他人信息、涉及合同承诺两类，不得按普通档排。
- 每次转接生成一条待办，字段含会话 ID、触发规则编号、接手岗位、起算时刻、响应截止、档位。
- 超时一级升值班主管，一级后再超时一个档位时长升客服负责人。
- 已响应但未解决不算响应超时（转入处理中）。
- 处理完成后必须回写知识缺口：由接手岗位在 1 个工作日内提交，内容脱敏。
- 客服不得给出报价口径、不得承诺合同条款、不得查询他人信息——一律转接。
- 时间基准为 naive datetime（不含时区），避免依赖系统 tzdata。
