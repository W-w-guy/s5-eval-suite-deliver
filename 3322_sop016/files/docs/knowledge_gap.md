# 知识缺口回写字段与规则（必做）

> 转接不能只解决问题就结束——**管家答不上来的原因必须回写**，否则下次还会转。

## 字段

| 字段 | 名称 | 要求 |
| --- | --- | --- |
| `gap_id` | 缺口编号 | 自动生成，形如 KG-YYYYMMDD-NN |
| `question` | 会员原问题 | 脱敏后原文，不含会员姓名、手机号与合同金额 |
| `attempted` | 管家已尝试的答案 | 最多 3 条，逐条标注置信度 |
| `fail_reason` | 答不上的原因 | 枚举：知识库缺失 / 条目过时 / 问题歧义 / 超出范围 |
| `suggest` | 建议补充的知识条目 | 一句话，须可被知识库直接采纳 |
| `rule_id` | 触发的转接规则 | R01~R06 |
| `owner` | 回写责任人 | 接手岗位，处理完成后 1 个工作日内提交 |

## 规则

1. 由**接手岗位**在处理完成后 **1 个工作日内**提交，不得转交客服代填；
2. `fail_reason` 为枚举值：知识库缺失 / 条目过时 / 问题歧义 / 超出范围；
3. 回写内容一律**脱敏**：不含会员姓名、手机号、合同金额；
4. 哪些规则必须回写：R01（小程序管家答不上来（连续 2）、R05（问题涉及他人信息（查询他人会）、R06（同一会话二次转接或会员明确表）；
5. 知识库负责人每周汇总一次，形成条目补充清单。

## 示例（虚构）

```json
{
  "gap_id": "KG-20260506-01",
  "question": "会员询问共享工位能否开具增值税专用发票",
  "attempted": ["说明可开票（置信度低）", "引用会员协议第 7 条（不适用）"],
  "fail_reason": "知识库缺失",
  "suggest": "补充「会员开票类型与申请入口」条目，明确专票/普票适用范围",
  "rule_id": "R01",
  "owner": "管家组客服"
}
```
