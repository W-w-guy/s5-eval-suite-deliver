# S5-EVAL-017 情报简报评测集 intel_brief.triage

## 一句话
35 条情报简报评测用例（常规 20 / 高相似干扰 10 / 全部与画像无关 5），每条 context 含 8~20 篇虚构资讯，
配 pairwise F1、分类准确率、NDCG@5 三项计算脚本与 runner，另有两项 forbidden 检查。

## 目录
```
data/cases.jsonl        35 条用例（含 gold 聚类/分类/前5、画像）
contexts/*.json         每条用例的资讯 context（8~20 篇）
tools/gen_cases.py      用例与 context 生成器（同源，gold 可取证）
tools/metrics.py        三项指标 + 簇对齐 + forbidden 检查
tools/eval_run.py       runner（聚类 -> 分类 -> 按画像排序 -> 指标 + 报告）
suite.yaml              套件定义（分布、门槛、forbidden、破坏开关说明）
reports/triage_v1.md    评测报告（含阈值敏感性表、逐条结果）
tests/                  24 个 pytest
verify_2022.py          4 条 AC 的 26 项断言
```

## 怎么跑
```bash
python tools/eval_run.py                       # 默认阈值 0.50，全达标 rc=0
python tools/eval_run.py --break-cluster --tag bad   # 打掉聚类，rc=1
python tools/eval_run.py --break-order               # 打掉排序
python tools/eval_run.py --leak                      # 触发 forbidden（引入 context 外资讯）
python -m pytest tests -q                            # 24 项
python verify_2022.py                                # 26 项 AC 断言
```

## 实测

| 指标 | 实测 | 门槛 |
|---|---|---|
| 聚类 pairwise F1 | **0.8763** | ≥0.80 |
| 分类准确率 | **0.8843** | ≥0.80 |
| 排序 NDCG@5 | **0.8607** | ≥0.80 |
| forbidden：同一事件出现两次 | 0 | 0 |
| forbidden：context 外资讯 | 0 | 0 |
| 全无关样本输出「本期无高相关资讯」 | **5/5** | 5/5 |

**聚类质量分解**：误合并 55 对、漏合并 21 对。误合并远多于漏合并，说明当前阈值偏松 ——
这与「干扰项与主事件措辞相似」的设定吻合，是这一档要考的核心难点。

## 五件必须先说清的事

**1. 三项指标都不是恒定的，都有破坏开关。**
`--break-cluster` 把每篇当独立事件 → F1 掉到 0.30 以下；`--break-order` 不看画像分数 →
NDCG@5 掉下来；`--leak` 引入 context 外资讯 → 触发 forbidden。**没有这三个开关，指标无法自证。**

**2. 分类准确率必须先做簇对齐，否则测的是「簇编号是否相同」。**
预测簇编号是 P01、金标是 E01，直接拿 id 比会全错（初版实测 0.0000）。
`metrics.align_clusters()` 按成员重叠做贪心匹配后再比类别，这一步不能省。

**3. 相似度阈值 0.50 是曲线拐点，不是挑出来的最高分。**
报告里有敏感性表：0.35 时误合并 155 对、0.60 时漏合并 224 对。0.50 处在两端都未失控的位置。
**阈值是唯一需要人工选定的参数，所以我把整条曲线放进报告，供复核。**

**4. 无关样本的画像 `interests` 必须为空。**
资讯池覆盖了政策/融资/行业动态/活动/竞品全部五类，只要 `interests` 非空就必然有事件命中，
这个档位就测不出东西。所以无关样本只靠「画像行业是否出现在正文」判相关，而行业是池外的深海养殖装备。

**5. 同事件多来源报道是「措辞不同、日期不同」，不是复制粘贴。**
生成器用 4 套表述模板 + 不同日期 + 不同来源，验证脚本里也断言了这一点
（30+ 条用例满足「文本全不同且日期不全相同」）。否则聚类退化成字符串比对，
pairwise F1 就没有区分度。

## 已知局限（如实写）
- 被测工具是 echo mock（文本相似度 + 关键词分类 + 画像打分），不读 gold 字段，可离线复现。
  它不代表真实模型水平；真模型应在聚类上更强、在分类上更依赖上下文。
- 误合并 55 对偏高：干扰项与主事件共享地名/句式，仅靠字符二元组 + 数字难以完全分开。
  真实系统应加「事件要素抽取（主体+动作+关键数字）」再比对，本包把 text_sim() 留成可替换接口。
- 35 条只够验证链路与门槛，不够估置信区间。
- gold_top5 允许并列，但实测生成的数据里未出现并列；若真实数据有并列，NDCG 计算需要扩展为并列增益。

## 与相邻工单的衔接

- 分类器可换成 #2264 的 policy_type 分类逻辑，事件分类目标一致。
